# 複合機 見積・比較表作成ツール

お客様からお預かりした **リース契約書** と **印刷明細書（カウンター明細）** を読み込み、
既存の Excel 帳票と同じ体裁の **御見積書** と **比較表** を、複数メーカー分まとめて
**PDF / Excel** で出力する Web アプリです。

```
資料アップロード → 自動読取 → 提案の自動組み立て → 内容の確認・調整 → PDF/Excel 出力
```

---

## できること

| 要望 | 実装 |
| --- | --- |
| カウンター明細・リース契約書を読み込んで自動判断 | PDF / 写真・画像 / Excel / CSV を解析し、印刷枚数・現行単価・月額リース料・リース期間・満了日・残債を抽出。写真とスキャンPDFはOCRで文字起こし |
| リース支払予定表からの読み取り | 「回数／支払日／リース料／残債」の表から、月額・回数・開始日・満了日・残債・残回数を組み立て |
| 複合機のスペックを自動判断 | 機種スペックDB（初期データ31機種）→ 無ければメーカー公式サイトから取得しDBへ保存 |
| 仕切価格に粗利を乗せて本体価格を算出 | 「仕切＋GP（粗利額）」「仕切＋粗利率」「目標月額リース料から逆算」「販売額計を直接入力」の4方式 |
| カウンター単価をエリア・CVで自動判別 | 研修資料の単価表（カラー枚数別／請求額別）＋メーカー別交渉レンジ＋京セラ全国担当エリア表（S/A/B/C/D）による判定 |
| PTF（代理店報酬）の自動計算 | 本体価格の10%。オプション・追加PC設定の上乗せ分は対象外 |
| 既存フォーマットの流用 | 御見積書・比較表とも既存Excelと同じ項目・並び（本体合計／お値引き／販売額計／カウンター料金／リースシミュレーション／比較表／売上換算効果） |
| PDF と Excel の両方で出力 | PDF は帳票ごと、Excel は1ブックにメーカー別シート＋各社比較シート |
| 複数メーカーを同時に出力 | メーカーを複数選択 → 見積書・比較表を一括生成し ZIP でダウンロード |

## 起動方法

```bash
cd apps/mfp-quote-tool
npm install
npx playwright install chromium   # PDF出力に使う Chromium（初回のみ）
npm run dev                       # http://localhost:3100
```

本番用に動かす場合は `npm run build && npm start`。

### 動作要件

- Node.js 20 以上（22 推奨）
- OCR（写真・スキャンPDFの読み取り）は追加インストール不要（学習データを同梱）
- PDF出力のみ Chromium が必要です。未インストールの場合、Excel は出力され、PDFは警告付きでスキップされます。
- 日本語フォントは実行しているPCのフォントを使います（Windows の游ゴシック／メイリオで確認）。

## データの持ち方

外部DBは不要で、すべて `data/` 配下の JSON です。

| ファイル | 内容 | Git |
| --- | --- | --- |
| `data/price-book.json` | 仕切表（定価・仕切率・仕切価格・明細ひな型・メーカー別注記・最低基本料金） | コミットする |
| `data/service-areas.json` | 京セラ 全国担当エリア表（1,905地区の対応ランク・離島区分） | コミットする |
| `data/devices.json` | 機種スペックDB。使うたびに育っていく | コミットする |
| `data/settings.json` | 自社情報・料率・単価表・PTF設定 | 除外（PCごとの設定） |
| `data/quotes/*.json` | 案件データ（顧客情報を含む） | 除外 |

> **取扱注意**
> `data/price-book.json` は仕切表（厳秘・弊社限り）の内容です。リポジトリは必ず非公開のまま運用してください。
> 保存先を変えたい場合は環境変数 `MFP_DATA_DIR` で任意のフォルダを指定できます
> （例：Googleドライブ上の共有フォルダ）。

## 計算ロジック（既存Excelとの対応）

### 見積書

```
本体合計   = 見積明細（定価）の合計
本体価格   = ①仕切価格 + GP（粗利額）        ← 既定
             ②目標月額リース料 ÷ リース料率  （既存Excelの「12800 / 1.66%」と同じ）
             ③仕切価格 ÷ (1 − 粗利率)
             ④直接入力
販売額計   = 本体価格 + オプション等の上乗せ分 + 旧リース残債精算
お値引き   = 販売額計 − 本体合計          （マイナス表示）
月額リース = 販売額計 × リース料率
```

リース料率の初期値は既存Excelと同じ **5年 1.95% / 6年 1.66% / 7年 1.45%** です。

### 旧リースの残債精算

現行リースに残債がある案件では、次の額を見積金額（リース対象額）に含めます。

```
残債精算 = 残債 + 現行の月額リース料 × 3ヶ月（解約事務手数料）
```

残債は支払予定表から自動で読み取り、無い場合は手入力できます。
この分はリース会社への立替なので **GP・NP には含めず、PTFの対象にもしません**。
月数の変更や機能自体のオン／オフは設定画面から行えます。

### カウンター料金

```
カウンター請求 = モノクロ枚数×単価 + フルカラー枚数×単価 + 2色カラー枚数×単価
                 （合計が最低基本料金を下回る場合は最低基本料金）
```

単価の自動判定は研修資料の2つの表を使い分けられます（設定画面で選択）。

- カラー印刷枚数で判定（〜500枚 0.7/7.0 … 10,001枚〜 0.40/4.0）
- 現行カウンター請求額で判定（〜15,000円 0.7/7.0 … 250,000円〜 0.40/4.0）

判定した単価は、仕切表に登録した **メーカーごとの交渉レンジ**（例：京セラ モノクロ0.4〜0.8／カラー4.0〜8.0）に収められます。

最低基本料金はメーカー別設定が優先されます。**京セラ 2,000円／東芝 1,500円**、
その他メーカーは条件が都度変わるため 0円で出力し、画面に「都度入力してください」と表示します。

### 保守対応エリアによる判定（京セラ 全国担当エリア表）

案件ごとに市区町村を選ぶと、対応ランクに応じて単価判定と注意表示が変わります。

| ランク | 内容 | ツールの動き |
| --- | --- | --- |
| S | 管轄事務所から1時間以内で現地到着 | 印刷枚数が少なくても **モノクロ0.7円／カラー7.0円** までの単価を提示（基準単価は設定画面で変更可） |
| A | 当日対応可能 | 同上 |
| B | 翌日対応 | メーカー交渉レンジの**上限側**の単価。画面に「当日保守ができず提案が難しいエリア」と警告 |
| C | 翌々日以降の対応 | 同上 |
| D | 対応不可 | 「京セラでの提案はできません」と警告 |

離島区分（離島A／離島B）がある地区は、追加費用・日数の注意を表示します。
収録しているのは京セラの担当エリア表のため、**単価判定に反映されるのは京セラの提案のみ**で、
他メーカーは参考情報として表示します（他メーカーのエリア表をいただければ同じ仕組みで追加できます）。

### 機種の自動選定

月間総印刷枚数 → 研修資料のグレード表（25枚機 3,000枚以下／35枚機 6,000枚以上／40枚機 8,000枚以上／
50枚機 15,000枚以上／60枚機 20,000枚以上／70枚機 30,000枚以上）→ 仕切表から該当グレード以上で最も近い機種。

### 収益

```
本体価格     = 販売額計 − オプション等の上乗せ分（明細で「PTF対象外」にした行）
GP（粗利益） = 販売額計 − 仕切価格
PTF          = 本体価格 × 10%
NP（純利益） = GP − PTF
```

フィニッシャー・ICカードリーダー等のオプションや追加のPC設定作業は、見積明細で
**「PTF対象外」** にチェックを入れてください。その分は値引きせずに販売額へ上乗せし、
PTFの計算対象から外れます。

## 要確認（初期値のまま使うと実態と合わない項目）

| 項目 | 初期値 | 備考 |
| --- | --- | --- |
| 2色カラー単価 | フルカラー単価 × 0.3 | 京セラ提案例（7.0円→2.0円）から。メーカーにより2色設定が無い場合があります |
| その他メーカーの最低基本料金 | 0円（都度入力） | 京セラ2,000円・東芝1,500円は設定済み。富士フイルム／シャープ／リコーは案件ごとに入力してください |
| リコーの仕切価格 | 幅の中央値 | 仕切表では「¥570,000〜¥610,000」のように幅があるため、案件ごとに実額を入力してください |
| 東芝・リコーの明細ひな型 | 既存の「見積用 定価」シートより | 一部で仕切表の定価と明細合計が一致しません（仕切表画面に差異を表示しています） |
| 京セラ以外の保守エリア判定 | なし | 担当エリア表をいただければ同じ仕組みで追加できます |

## 資料の読み取りについて

### 対応する形式

| 形式 | 読み取り方 |
| --- | --- |
| PDF（文字データあり） | テキストを座標から行に組み直して解析。最も精度が高い |
| PDF（スキャン画像のみ） | ページを画像に描き起こしてOCR（先頭4ページまで） |
| 写真・画像（JPEG / PNG / HEIC 等） | OCR。iPhoneのHEICは自動でJPEGに変換 |
| Excel / CSV | セルをそのまま読み取り |

### 自動で拾えるもの

- 「前回指針・今回指針・使用枚数・単価・金額」の並び（指針の差＝枚数、枚数×単価＝金額 で検証）
- 「チャージ枚数 1〜1,000 / 1001〜」のような段階単価（枚数を合算し、加重平均単価に変換）
- 機番ごとの複数台明細（機番でブロック分割）。同じ明細を写真とPDFで二重に渡しても合算しません
- 和暦（令和6年4月1日 / R6.4.1）と西暦の混在
- 複数月の明細（期間から月数を割り出して月平均に換算）
- 支払予定表の「回数／支払日／リース料／残債」（回数や支払日がOCRで崩れても、毎月払いであることを利用して補完）

### OCRの仕組みと限界

OCRは tesseract.js（WASM）で、日本語・英語の学習データを `data/tessdata` に同梱しています。
別途ソフトのインストールは不要で、インターネットに出られない環境でも動きます。

読み取りは、無加工／解像度違い／用紙の切り出し＋二値化＋傾き補正、といった数通りを試し、
「表として読めている」ものを自動で採用します。1ページあたり2〜8秒ほどかかります。

**精度は原本の写り方に大きく左右されます。** スキャンやPDFはほぼ正確に読めますが、
斜めに撮った写真・影の強い写真・低解像度の写真では、表の行が崩れて読み取れないことがあります。
写真で撮る場合は次を守ると成功しやすくなります。

- 書類を画面いっぱいに、**正面から**撮る（傾けない）
- 影が入らない明るい場所で撮る
- ピントを合わせ、圧縮の強い設定は避ける

読み取り結果は必ず画面で確認し、必要なら手入力で修正してください（金額・枚数はすべて編集できます）。
どの資料をどう読んだか（OCRの有無・認識行数）は解析結果の一覧に表示されます。
