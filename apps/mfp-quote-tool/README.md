# 複合機 見積・比較表作成ツール

お客様からお預かりした **リース契約書** と **印刷明細書（カウンター明細）** を読み込み、
既存の Excel 帳票と同じ体裁の **御見積書** と **比較表** を、複数メーカー分まとめて
**PDF / Excel** で出力する Web アプリです。

```
資料アップロード → 自動読取 → 提案の自動組み立て → 内容の確認・調整 → PDF/Excel 出力
```

---

## できること

| 要望 | 実装 |
| --- | --- |
| カウンター明細・リース契約書を読み込んで自動判断 | PDF / 写真・画像 / Excel / CSV を解析し、印刷枚数・現行単価・月額リース料・リース期間・満了日・残債を抽出。PDF・写真は**AI（Claude）が直接読み取り**、AIを使わない場合はOCRで文字起こし |
| 複数月ぶんの明細から平均枚数 | 明細の対象期間から月数を割り出して月平均に換算し、見積書・比較表に「（2025/03-2025/08平均印刷枚数）」と注記 |
| リース支払予定表からの読み取り | 「回数／支払日／リース料／残債」の表から、月額・回数・開始日・満了日・残債・残回数を組み立て |
| 複合機のスペックを自動判断 | 機種スペックDB（初期データ31機種）→ 無ければメーカー公式サイトから取得しDBへ保存 |
| 仕切価格に粗利を乗せて本体価格を算出 | 「仕切＋GP（粗利額）」「仕切＋粗利率」「目標月額リース料から逆算」「販売額計を直接入力」の4方式 |
| カウンター単価をエリア・CVで自動判別 | 研修資料の単価表（カラー枚数別／請求額別）＋メーカー別交渉レンジ＋京セラ全国担当エリア表（S/A/B/C/D）による判定 |
| PTF（代理店報酬）の自動計算 | 本体価格の10%。オプション・追加PC設定の上乗せ分は対象外 |
| 既存フォーマットの流用 | 御見積書・比較表とも既存Excelと同じ項目・並び（本体合計／お値引き／販売額計／カウンター料金／リースシミュレーション／比較表／売上換算効果） |
| PDF と Excel の両方で出力 | PDF は帳票ごと、Excel は1ブックにメーカー別シート＋各社比較シート |
| 複数メーカーを同時に出力 | メーカーを複数選択 → 見積書・比較表を一括生成し ZIP でダウンロード |

## 起動方法（Windows・コマンド不要）

1. Node.js を入れる（PCごとに1回だけ）。コマンドプロンプトで `winget install OpenJS.NodeJS.LTS`、
   または https://nodejs.org の LTS版インストーラを実行し、PCを再起動
   - `start.bat` は PATH に無くても `C:\Program Files\nodejs` などの既定の場所を探します
2. ZIPで受け取った場合は、**必ず先に展開する**（右クリック →「すべて展開」）
   - ZIPを開いたまま中の `start.bat` を実行しても動きません。`start.bat` はそれを検知して理由を表示します
3. 展開したフォルダの **`start.bat` をダブルクリック**
4. AIのAPIキー（PDF・写真の読み取りに使う）は、画面の「設定」から登録します

初回は必要な部品の取得に数分かかり、そのあとブラウザが自動で開きます。
2回目以降は `start.bat` をダブルクリックするだけで起動します。終了は黒い画面を閉じるか Ctrl + C。

`start.bat` は cmd だけで書いてあり、PowerShell を呼びません。
実行ポリシーやダウンロードファイルのブロックで起動できない、という事故を避けるためです。
起動の経過は同じフォルダの `start-log.txt` に残るので、動かないときはこれを見てください。

### 起動しないとき

| 症状 | 原因と対処 |
| --- | --- |
| 黒い画面が一瞬も出ない | ZIPの中から実行している／SmartScreenに止められている。ZIPを展開し、ZIPのプロパティで「許可する」にチェックしてから展開し直す |
| 「ZIPファイルの中から実行しています」 | 右クリック →「すべて展開」で展開してから、出てきたフォルダの `start.bat` を実行する |
| 「Node.js が見つかりません」 | そのPCに Node.js が入っていない。コマンドプロンプトで `winget install OpenJS.NodeJS.LTS`、または https://nodejs.org の LTS版インストーラを実行し、PCを再起動 |
| 「部品の取得（npm install）に失敗しました」 | 社内ネットワークの制限。画面の内容と `start-log.txt` を送る |

### コマンドで起動する場合

```bash
cd apps/mfp-quote-tool
npm install
npx playwright install chromium   # PDF出力に使う Chromium（初回のみ）
npm run dev                       # http://localhost:3100
```

本番用に動かす場合は `npm run build && npm start`。

### 動作要件

- Node.js 20 以上（22 推奨）
- AIでの読み取りを使う場合は Anthropic の APIキー（[Claude Console](https://platform.claude.com/settings/keys) で発行）
- OCR（AIを使わない場合の読み取り）は追加インストール不要（学習データを同梱）
- PDF出力のみ Chromium が必要です。未インストールの場合、Excel は出力され、PDFは警告付きでスキップされます。
- 日本語フォントは実行しているPCのフォントを使います（Windows の游ゴシック／メイリオで確認）。

### 保存先（Googleドライブ）

`start.bat` から起動すると、データは既定で次のフォルダに保存されます。

```
G:\共有ドライブ\★Kevin\▲0Claude\複合機見積作成ツール\data
```

初回起動時に、仕切表・機種DB・保守エリア表・OCR辞書がこのフォルダへ自動でコピーされ、
以降はここが正となります。3台のPCで同じ案件・同じマスタを共有できます。
別の場所にしたい場合は、アプリのフォルダに `data-dir.txt` を作り、1行目にパスを書いてください。

プログラム本体（`node_modules` は数万ファイル）はPC内（C:）に置いてください。
Googleドライブ上に置くと同期の競合で動作が不安定になります。

> **取扱注意**
> `data/price-book.json` は仕切表（厳秘・弊社限り）の内容です。リポジトリは必ず非公開のまま運用してください。

## 計算ロジック（既存Excelとの対応）

### 見積書

```
本体合計   = 見積明細（定価）の合計
本体価格   = ①仕切価格 + GP（粗利額）        ← 既定
             ②目標月額リース料 ÷ リース料率  （既存Excelの「12800 / 1.66%」と同じ）
             ③仕切価格 ÷ (1 − 粗利率)
             ④直接入力
販売額計   = 本体価格 + オプション等の上乗せ分 + 旧リース残債精算
お値引き   = 販売額計 − 本体合計          （マイナス表示）
月額リース = 販売額計 × リース料率
```

リース料率の初期値は既存Excelと同じ **5年 1.95% / 6年 1.66% / 7年 1.45%** です。

### 旧リースの残債精算

現行リースに残債がある案件では、次の額を見積金額（リース対象額）に含めます。

```
残債精算 = 残債 + 現行の月額リース料 × 3ヶ月（解約事務手数料）
```

残債は支払予定表から自動で読み取り、無い場合は手入力できます。
この分はリース会社への立替なので **GP・NP には含めず、PTFの対象にもしません**。
月数の変更や機能自体のオン／オフは設定画面から行えます。

### カウンター料金

```
カウンター請求 = モノクロ枚数×単価 + フルカラー枚数×単価 + 2色カラー枚数×単価
                 （合計が最低基本料金を下回る場合は最低基本料金）
```

単価の自動判定は研修資料の2つの表を使い分けられます（設定画面で選択）。

- カラー印刷枚数で判定（〜500枚 0.7/7.0 … 10,001枚〜 0.40/4.0）
- 現行カウンター請求額で判定（〜15,000円 0.7/7.0 … 250,000円〜 0.40/4.0）

判定した単価は、仕切表に登録した **メーカーごとの交渉レンジ**（例：京セラ モノクロ0.4〜0.8／カラー4.0〜8.0）に収められます。

最低基本料金はメーカー別設定が優先されます。**京セラ 2,000円／東芝 1,500円**、
その他メーカーは条件が都度変わるため 0円で出力し、画面に「都度入力してください」と表示します。

### 保守対応エリアによる判定（京セラ 全国担当エリア表）

案件ごとに市区町村を選ぶと、対応ランクに応じて単価判定と注意表示が変わります。

| ランク | 内容 | ツールの動き |
| --- | --- | --- |
| S | 管轄事務所から1時間以内で現地到着 | 印刷枚数が少なくても **モノクロ0.7円／カラー7.0円** までの単価を提示（基準単価は設定画面で変更可） |
| A | 当日対応可能 | 同上 |
| B | 翌日対応 | メーカー交渉レンジの**上限側**の単価。画面に「当日保守ができず提案が難しいエリア」と警告 |
| C | 翌々日以降の対応 | 同上 |
| D | 対応不可 | 「京セラでの提案はできません」と警告 |

離島区分（離島A／離島B）がある地区は、追加費用・日数の注意を表示します。
収録しているのは京セラの担当エリア表のため、**単価判定に反映されるのは京セラの提案のみ**で、
他メーカーは参考情報として表示します（他メーカーのエリア表をいただければ同じ仕組みで追加できます）。

### 機種の自動選定

月間総印刷枚数 → 研修資料のグレード表（25枚機 3,000枚以下／35枚機 6,000枚以上／40枚機 8,000枚以上／
50枚機 15,000枚以上／60枚機 20,000枚以上／70枚機 30,000枚以上）→ 仕切表から該当グレード以上で最も近い機種。

### 収益

```
本体価格     = 販売額計 − オプション等の上乗せ分 − 旧リース残債精算
GP（粗利益） = 本体価格 + オプション等の上乗せ分 − 仕切価格
               （残債精算はリース会社への立替なので含めない）
PTF          = 本体価格 × 10%
NP（純利益） = GP − PTF
```

フィニッシャー・ICカードリーダー等のオプションや追加のPC設定作業は、見積明細で
**「PTF対象外」** にチェックを入れてください。その分は値引きせずに販売額へ上乗せし、
PTFの計算対象から外れます。

## 資料の読み取りについて

### 対応する形式

| 形式 | 読み取り方 |
| --- | --- |
| PDF（文字データ有無を問わず） | AI（Claude）にPDFのまま渡して読み取り。AIを使わない設定のときは、文字データがあれば座標から行を組み直し、無ければOCR |
| 写真・画像（JPEG / PNG / HEIC 等） | AI（Claude）が画像を直接読み取り。iPhoneのHEICは自動でJPEGに変換。AIを使わない設定のときはOCR |
| Excel / CSV | セルをそのまま読み取り（AIは使いません） |

### 自動で拾えるもの

- 「前回指針・今回指針・使用枚数・単価・金額」の並び（指針の差＝枚数、枚数×単価＝金額 で検証）
- 「チャージ枚数 1〜1,000 / 1001〜」のような段階単価（枚数を合算し、加重平均単価に変換）
- 機番ごとの複数台明細（機番でブロック分割）。同じ明細を写真とPDFで二重に渡しても合算しません
- 和暦（令和6年4月1日 / R6.4.1）と西暦の混在
- 複数月の明細（期間から月数を割り出して月平均に換算し、「（2025/03-2025/08平均印刷枚数）」と見積書・比較表に注記）
- 支払予定表の「回数／支払日／リース料／残債」（回数や支払日がOCRで崩れても、毎月払いであることを利用して補完）

### AIによる読み取り（既定）

スキャン書類やスマホ写真は、文字起こし（OCR）だけでは表の行が崩れてしまい、
「どの数字が枚数で、どの数字が単価か」を取り違えます。
そこで PDF・写真は **Claude にそのまま渡し、書類の意味を踏まえて読み取らせています。**

- 設定：`/settings` の「AIによる書類の読み取り」で ON / OFF、APIキー、モデル、1ファイルの最大ページ数を指定
- APIキーの置き場所は次の3通り（上から順に探します）
  1. 設定画面で入力したキー（保存先の `settings.json`）
  2. 環境変数 `ANTHROPIC_API_KEY`
  3. 保存先の `api-key.txt`（`start.bat` は起動時にこのファイルを読み込みます）
  いずれも平文で保存されるため、共有ドライブに置いている場合は共有相手にも見えることにご注意ください
- 読み取りの結果は「AI読み取り」バッジと、使ったトークン数・概算費用として画面に表示されます
  （A4数枚の書類1件で数円〜十数円が目安）
- AIが使えないとき（キー未設定・通信エラー等）は警告を出したうえで、自動的にOCRへ切り替えます
- お客様の書類はAnthropicのAPIへ送信されます。社外に出せない資料を扱う場合は、
  設定でAIをOFFにしてOCRのみで運用してください

AIには次のことをさせています。

- 和暦（令和6年4月1日 / R6.4.1）の西暦への変換
- 「今回指針 − 前回指針」による枚数の算出と、枚数欄との突き合わせ
- 複数月・複数台が1枚に並んだ明細を、期間ごと・機械ごとに分けて返す
- 読み取れない項目は推測せず空欄にし、判断に迷った点を注記として返す

返ってきた値はプログラム側で検算しています（単価が100円を超える、金額が入っている欄が空、
日付の形式が違う、といったものは採用しません）。

### OCRの仕組みと限界（AIを使わない場合）

OCRは tesseract.js（WASM）で、日本語・英語の学習データを `data/tessdata` に同梱しています。
別途ソフトのインストールは不要で、インターネットに出られない環境でも動きます。

読み取りは、無加工／解像度違い／用紙の切り出し＋二値化＋傾き補正、といった数通りを試し、
「表として読めている」ものを自動で採用します。1ページあたり2〜8秒ほどかかります。

**精度は原本の写り方に大きく左右されます。** スキャンやPDFはほぼ正確に読めますが、
斜めに撮った写真・影の強い写真・低解像度の写真では、表の行が崩れて読み取れないことがあります。
写真で撮る場合は次を守ると成功しやすくなります。

- 書類を画面いっぱいに、**正面から**撮る（傾けない）
- 影が入らない明るい場所で撮る
- ピントを合わせ、圧縮の強い設定は避ける

読み取り結果は必ず画面で確認し、必要なら手入力で修正してください（金額・枚数はすべて編集できます）。
どの資料をどう読んだか（AI / OCR / テキスト抽出の別と認識行数）は解析結果の一覧に表示されます。
