# 基幹システムに組み込むときの下ごしらえ

このツールは今、**1台のWindows PCで動く単独のアプリ**として作ってあります。
Denrai統合基幹システムの一部にするとき、どこが引っかかるのか、
どこはもう準備してあるのかを、1か所にまとめたものです。

> このファイルは「設計の決定」ではなく「地図」です。
> 基幹システム側の形が決まったら、下の **「決めてほしいこと」** に答えを入れて、
> それから作りはじめます。

---

## 1. いま、どこが「1台のPC向け」なのか

| 部分 | いまの作り | 基幹システムに入るとどうなるか | 準備 |
| --- | --- | --- | --- |
| 案件データ | `data/quotes/*.json`（1案件1ファイル） | 全社で共有するのでDBかAPIへ | 入口は `src/lib/store.ts` だけ。差し替えはここ |
| 利用者 | `data/users.json`＋このツールのログイン画面 | 入口は基幹システム側に一本化 | **済**（下の3） |
| 仕切表 | `data/price-book.json`（Gitに入れて配布） | 価格マスタは基幹システムが持つ | 読む口は `getPriceBook()` だけ |
| 機種スペックDB | `data/devices.json` | 同上（共有マスタ） | 読む口は `listDevices()` だけ |
| 設定 | `data/settings.json` | 会社情報は基幹システムから、印字の体裁はこのまま | 読む口は `getSettings()` だけ |
| 見積番号 | Apps Script経由で台帳スプレッドシートから採番 | 基幹システムの採番に寄せる | 口は `src/lib/quote-register.ts` |
| アップロード画像 | `data/uploads/` に置く | 共有ストレージかオブジェクトストレージへ | 口は `src/lib/uploads.ts` |
| PDFの生成 | Playwright（Chromium）を同梱して起動 | サーバーにChromiumが要る | 下の4を参照 |
| 置き場所 | `http://localhost:3000` 直下 | ポータルの `/mfp` などにぶら下がる | **済**（下の2） |

読み書きの口が `store.ts` の1ファイルに集まっているので、
**保存先の差し替えは、画面やAPIを触らずにできます。** ここは最初から
そうなっていたので、作り直しは要りません。

---

## 2. 置き場所（済）

ポータルの下にぶら下げるときは、環境変数ひとつで移せます。

```
MFP_BASE_PATH=/mfp
```

画面のリンクも、画像も、APIの宛先も、すべてこれを基準に出ます。
読んでいるのは `next.config.ts` と `src/lib/config.ts` の2か所だけです。

---

## 3. 誰がログインしているか（済）

**いま（単独で動かす）**

```
（指定なし）    … このツールのログイン画面を使う
```

**基幹システムに入れたあと**

```
MFP_IDENTITY=header
MFP_IDENTITY_HEADER=x-denrai-user     （既定。変えてもよい）
MFP_PROXY_TOKEN=〈基幹システムと共有する合言葉〉
```

こうすると、このツールのログイン画面は使わなくなり、
前に立つ基幹システムが「確かめ済みの利用者」をヘッダーで渡す形になります。
パスワードを2か所で持たずに済みます。

> **注意：** ヘッダーは誰でも名乗れます。`MFP_IDENTITY=header` は
> **前段が必ずヘッダーを上書きする構成でのみ**使ってください。
> `MFP_PROXY_TOKEN` を設定すると、合言葉の合わないリクエストは
> 名乗りを受け付けません。直接インターネットに出すサーバーでは使わないこと。

コードの上では、「いま操作しているのは誰か」を答える場所を
`src/lib/session.ts` の1ファイルに集めてあります。
画面もAPIもクッキーを直接読んでいないので、入口を移すときに直すのはここだけです。

## 4. 先に決めておかないと、あとで高くつくもの

### (a) 案件に「誰のものか」を残す（済）

`Quote` に `createdBy` / `updatedBy`（ログインID）を入れました。
削除の記録にも `deletedByUser` を足しています。

1人で使っているうちは要りませんが、全社で共有すると
「これは誰の案件か」が必ず要ります。**共有を始めてから足すと、
それまでの案件が全部「作った人が分からない」まま残ります。**
いま入れておけば、移行のときにそのまま使えます。

ログインの前に作られた案件は空のままですが、誰かが一度直せば入ります。

### (b) PDFの生成にChromiumが要る

見積書・比較表のPDFは、HTMLをChromiumで印刷して作っています。
Excelの体裁をそのまま出すためで、ここは変えないほうがよいところです。

サーバーに置くなら、そのサーバーにChromiumが要ります。
Windowsサーバーなら今のまま動きます。Linuxのコンテナに載せるなら
日本語フォント（メイリオ相当）も一緒に入れてください。
**フォントが無いと、文字が□になったまま気づかずにお客様に出てしまいます。**

### (c) 複数人が同時に触ったとき

いまは1案件1ファイルで、最後に保存した人の内容で上書きされます。
1人で使っている間は起きませんが、共有すると起きます。
DBに移すときに、更新時刻での衝突検知を一緒に入れるのが安全です。

## 6. 置き場所に関する環境変数のまとめ

| 環境変数 | 既定 | 何のため |
| --- | --- | --- |
| `MFP_DATA_DIR` | アプリ同梱の `data/` | データの保存先 |
| `MFP_BASE_PATH` | （なし＝直下） | ポータルの下にぶら下げるときの住所 |
| `MFP_IDENTITY` | `local` | `header` にすると基幹システムから利用者を受け取る |
| `MFP_IDENTITY_HEADER` | `x-denrai-user` | 利用者を載せてくるヘッダー名 |
| `MFP_PROXY_TOKEN` | （なし） | 基幹システムからの呼び出しであることの合言葉 |

会社の情報・仕切率・リース料率といった**業務の中身は、環境変数には置きません**。
これらは設定画面（`data/settings.json`）側です。
