# Denrai統合基幹システムへの組み込み

## 先に、前提をひとつ訂正します

最初にこの文書を書いたとき、統合基幹システムを**サーバーのあるWebシステム**だと思い込み、
その前提で下ごしらえをしました。調べ直したところ、実際は違いました。

統合基幹システムは **claude.aiのアーティファクト**です。
つまり**ブラウザの中だけで動く1枚のページ**で、サーバーがありません。
各ツールは Shadow DOM の中に画面を作る形で埋め込まれます。

これは昇降機検査報告書比較ツール（EvHikaku）が先に通った道で、
`tools/ev-hoshu-hikaku/integration/README.md` に組み込み方が書かれています。
同じ形に合わせるのが筋です。

この違いは小さくありません。**このツールの中には、ブラウザでは動かせない部分があります。**
下でひとつずつ仕分けします。

---

## 1. 結論から

| | |
| --- | --- |
| **そのまま持っていけるもの** | 料金の計算・見積書と比較表の組版（＝このツールの中心） |
| **持っていけないもの** | AI書類読み取り・Excel出力・台帳からの見積番号採番 |
| **作り替えが要るもの** | 保存先・PDF化・ログイン |

中心部分が動くことは、**実際に確かめました**。
`integration/browser-core.ts` を50KBほどに固めてブラウザに読み込ませ、
サーバーを一切使わずに見積書を組ませたところ、
いまサーバーで作っているPDFと**同じものが出ました**（金額も体裁も一致）。

```
npx esbuild integration/browser-core.ts --bundle --format=iife \
  --platform=browser --target=es2020 --alias:@=./src \
  --global-name=MfpCore --outfile=integration/mfp-core.js
```

## 2. ひとつずつの仕分け

### そのまま持っていけるもの

| 中身 | ファイル |
| --- | --- |
| 料金の計算（仕切・粗利・リース料率・カウンター単価） | `src/lib/pricing.ts` |
| 複数台の計算 | `src/lib/fleet.ts` |
| 見積書・比較表・複数台比較表の組版 | `src/lib/export/html.ts` |
| ご提案書の文面組み立て | `src/lib/proposal-doc.ts` |

Nodeのものを取り込んでいないので、手を入れずに動きます。
**この状態を保つため、`src/lib/browser-safe.test.ts` で見張っています。**
うっかり `node:fs` などを足すとテストが落ちます。

### 持っていけないもの（アーティファクトの制約）

| 機能 | なぜ | どうするか |
| --- | --- | --- |
| **AI書類読み取り** | アーティファクトから外部APIを呼べない | ローカル版で読み取り、データだけ共有する／ホストのAI機能に差し替える |
| **Excel出力** | `.xlsx` がclaude.ai側の保存許可リストに無い（EvHikakuも同じ壁） | ローカル版に残す |
| **見積番号の採番** | Apps Script（script.google.com）を呼べない | 番号はローカル版で取る／ホスト側に採番を作る |
| **OCR** | tesseract.jsはブラウザでも動くが、辞書が12MBある | 読み取りはローカル版に寄せるのが現実的 |

> この3つはいずれも「このツールの作りが悪い」のではなく、
> **アーティファクトという置き場所の制約**です。EvHikakuも同じ3点で止まっています。
> 2つのツールが同じ壁に当たっているので、置き場所そのものを
> 考え直す価値はあると思います（下の5）。

### 作り替えが要るもの

| 中身 | いま | 組み込み版 |
| --- | --- | --- |
| 保存先 | `src/lib/store.ts`（JSONファイル） | ホストの保存先に繋ぎ替え。読み書きの口はこの1ファイルだけ |
| 値の読み込み | `src/lib/calc-context.ts` | 設定・仕切表をホストから渡す形に |
| PDF化 | `src/lib/export/pdf.ts`（Chromiumを起動） | `window.print()`。組版は同じHTMLなので、紙の体裁は変わらない |
| ログイン | `src/lib/auth.ts` / `session.ts` | ホスト側が持つ（すでにk.kevin@denrai.netで施錠済みとのこと） |

## 3. 進め方の案

### 案A：ポータルから起動するだけ（いちばん安全）

統合基幹システムにタイルを置き、押したらこのツールを別途開く。
**機能は何も失われません。** 「1つのシステムに見える」度合いはいちばん低い。

### 案B：見る・刷るだけを組み込む（おすすめ）

案件を**作る**作業（書類の読み取り・Excel・採番）はローカル版に残し、
**見る・刷る**を統合基幹システムの中に入れる。
上で確かめたとおり、計算と組版はそのまま動くので、作り替えはほぼ保存先だけです。

日常は「営業がポータルで過去の見積を開いて刷る」「新規作成はローカル版」になります。
EvHikakuが落ち着こうとしている形とも揃います。

### 案C：全部ブラウザへ移す

AI読み取り・Excel・採番を捨てるか、作り直すことになります。
いまのツールの値打ちのかなりの部分がそこにあるので、おすすめしません。

## 4. 前回の下ごしらえのうち、残るもの・外れたもの

| したこと | いまの評価 |
| --- | --- |
| 案件に `createdBy` / `updatedBy` を残す | **残る。** どの案でも要る |
| 「いま操作しているのは誰か」を `session.ts` に集約 | **残る。** ホストに寄せるときの差し替え口 |
| トップページが入口の照合から漏れる不具合の修正 | **残る。** 単体で動かすときの実害ある不具合だった |
| `MFP_BASE_PATH`（ぶら下げる住所） | **外れた。** サーバー前提の話。害はないので残置 |
| `MFP_IDENTITY=header`（前段から利用者を受け取る） | **外れた。** 同上。案Aで別サーバーに置くなら生きる |

---

## 5. 決めてほしいこと

1. **案A・案B・案Cのどれにしますか。**（おすすめは案B）
2. **案件データはどこに置きますか。** ホストの保存先か、ツール専用か。
   ブラウザのlocalStorageは**見ている人のブラウザの中だけ**に残るので、
   複数人で案件を共有するなら使えません。
3. **統合基幹システムを、このままアーティファクトで進めますか。**
   2つのツールが「外部API・Excel保存」で同じ壁に当たっています。
   全社の基幹として育てるなら、どこかで置き場所の判断が要ると思います。

## 6. 単体で動かすときの環境変数（参考）

| 環境変数 | 既定 | 何のため |
| --- | --- | --- |
| `MFP_DATA_DIR` | 同梱の `data/` | データの保存先 |
| `MFP_BASE_PATH` | （なし＝直下） | サーバーとして別の場所にぶら下げるとき |
| `MFP_IDENTITY` | `local` | `header` で前段から利用者を受け取る |
| `MFP_IDENTITY_HEADER` | `x-denrai-user` | そのヘッダー名 |
| `MFP_PROXY_TOKEN` | （なし） | 前段を通ったことの合言葉 |
